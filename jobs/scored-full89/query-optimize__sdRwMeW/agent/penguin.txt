## What I changed

The original query ran two correlated subqueries for every qualifying word:

1. `top_synsetid` — a `GROUP BY` + `ORDER BY COUNT(*) DESC ... LIMIT 1` over the whole `senses` table, re-scanning ~212K rows per word.
2. `top_synset_sense_count` — which repeated essentially the same correlated work.

Since there are ~17,834 qualifying words, this caused hundreds of millions to billions of row scans (the original took ~2m45s).

## Optimized approach

- Compute all per-word aggregates (`total_synsets`, `total_senses`, `distinct_domains`, `distinct_posids`) in one set-based pass with `GROUP BY` (CTE `agg`).
- Compute per `(wordid, synsetid)` sense counts once in a single pass (CTE `ws`).
- Use a window function `ROW_NUMBER() OVER (PARTITION BY wordid ORDER BY cnt DESC, synsetid ASC)` to directly pick the top synset (CTE `top`), which preserves the original tie-break semantics exactly.
- Carry the count through the CTE instead of re-counting the senses with another correlated subquery.
